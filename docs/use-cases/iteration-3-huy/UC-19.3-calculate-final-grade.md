# UC-19.3 - Calculate Final Grade

Current cross-cutting rules: [completion, separate Sections and Assignment files](COMPLETION_UPDATE.md).


## 1. ID and Name
UC-19.3 - **Calculate Final Grade**. ID preserved from the requested Iteration 3 scope.

## 2. Implementation Status
Original UC ID/name retained for traceability. The user explicitly replaced weighted final-grade calculation with refreshing the shared Course completion result. Implemented; no weighted average, rounding, provisional grade or independent final pass threshold remains.

## 3. Created By, Date and Iteration
Tạ Gia Huy - CE182405 - HuyTGCE182405. Created **2026-11-08**. Iteration **3**.

## 4. Actors
Primary Actor: **Teacher owning the Course**.
Secondary Actors: None; databases and storage are internal system components.

## 5. Description
Refresh the single Course-completion result from all required Lesson/video activity and latest Quiz/current Assignment outcomes. This UC no longer calculates a weighted numeric final grade.

## 6. Trigger
Teacher opens Gradebook or selects Refresh Results.

## 7. Preconditions
- PRE-1: Teacher is signed in, active, email verified and not suspended from teaching.
- PRE-2: The selected Course and required parent resources exist and are not deleted.
- PRE-3: Teacher owns the Course; content changes additionally require an editable Course status.
- PRE-4: Actor supplies the required inputs listed in section13.

## 8. Postconditions
Success: identical source records yield the same readiness and missing requirements in Student progress, Gradebook/report and certificate gates. No grade policy or averaged grade is stored. Failure leaves data unchanged.

## 9. Normal Flow
1. Teacher opens Gradebook or selects Refresh Results.
2. System checks authentication and Course ownership.
3. System loads published accessible Lessons/Quizzes, Assignments and enrolled Students.
4. System selects each Quiz latest submitted attempt and each Assignment current accepted submission.
5. System verifies Lesson completion, video threshold and every assessment pass condition through the shared evaluator.
6. System displays Requirements met or Incomplete, plus unmet activities, with a refresh success toast.

## 10. Alternative Flows
AF1.NF4: In-progress Quiz attempt exists: retain the latest submitted result; continue NF5.
AF2.NF5: Missing/ungraded work or numeric Assignment without a pass threshold: show incomplete and unmet requirements; continue NF6.
AF3.NF5: No required activities: incomplete; continue NF6.

## 11. Exceptions
EX0.NF2: Authentication/ownership fails:401/403 or404 for unavailable resources; stop.
EX1.NF3: Persistence failure: show persistent error and error toast, preserve existing data.
EX2.NF1: A legacy client writes /gradebook/policy: verify ownership, then return410; do not write.

## 12. Business Rules
I3-HUY-R06/R07/R08 were superseded by the explicit owner follow-up in COMPLETION_UPDATE.md. Every required activity must pass; use latest accepted work. No best-attempt or separate final threshold.

## 13. Input/Data Validation
Owned Course ID and valid pagination. No weight, rounding or final-threshold fields. Quiz pass threshold is its existing configured0-100 value; numeric Assignment uses its configured same-scale threshold. Deadline acceptance is checked when submitting, inclusive at equality.

## 14. Priority and Frequency of Use
Priority: High (Proposed planning value). Frequency: As needed during Course preparation, assessment or review; actual usage frequency is not measured.

## 15. Other Information and Assumptions
Existing activity-progress percentages are not numerical grade averages. Both certificate issuance paths consume the same eligibility gate; new work can change current readiness while historical certificate records remain stored.

## 16. Acceptance Criteria
- AC-1: Normal flow yields the stated success postcondition with persisted/source-aligned values.
- AC-2: A different Teacher and an unauthenticated user cannot perform the protected action.
- AC-3: Each validation and alternate flow above preserves the documented zero/null, relation, time or revision distinction.
- AC-4: UI exposes loading/busy, empty where applicable, and error states without claiming success on failure.
- AC-5: Repeated reads/calculation do not create duplicate grades; writes follow their documented update semantics.
