## 4. Actors
Primary Actor: **Teacher owning the Course**.

## 5. Description
Give Assignment Feedback within an owned Course. The Actor-System interaction below describes implemented behavior; unimplemented extensions remain in section18.

## 6. Trigger
Teacher chooses the corresponding action in Teacher submission detail; Student Learn Assignment modal.

## 7. Preconditions
- PRE-1: Teacher is signed in, active, email verified and not suspended from teaching.
- PRE-2: The selected Course and required parent resources exist and are not deleted.
- PRE-3: Teacher owns the Course; content changes additionally require an editable Course status.
- PRE-4: An existing submitted Assignment answer is selected; numerical grading requires an explicitly configured scale.

## 8. Postconditions
**Success:** Feedback is updated independently. Existing grade and grading metadata are preserved.

**Failure:** No unauthorized data is exposed or updated. Validation/conflict failures preserve existing records. Technical multi-step failure recovery/limits are described in sections11 and15; full cross-collection transactions are not implied.

## 9. Normal Flow
1. Teacher opens submission details.
2. System authenticates the Teacher and verifies ownership through the Assignment Course.
3. Teacher enters or updates feedback and selects Save Feedback Only.
4. System validates text and the current submission revision.
5. System stores feedback and its author/time without changing score, status or grading time.
6. System displays the saved feedback to the Teacher and its submitting student through the protected learning view.

## 10. Alternative Flows
AF1.NF3: Teacher clears feedback. System stores an empty string and increments revision; continue NF6.
AF2.NF3: Teacher saves feedback together with a grade. Continue the UC-17.4 flow instead of creating a second feedback record.

## 11. Exceptions
EX0.NF2: Authentication, teaching permission or ownership fails. System returns401/403 (or404 for unavailable parent resources), exposes no protected result, and ends the use case.

EX1.NF4: Non-string or more than10000 characters: reject and return NF3.
EX2.NF5: Concurrent edit/resubmission: return conflict; reload NF1 before retrying.

## 13. Input/Data Validation
feedback: string, trimmed, maximum10000 characters; empty allowed to clear. revision: nonnegative integer; UI sends current revision. Plain text/React escaping is used, not executable HTML.
