## 5. Description
Set Assignment Deadline within an owned Course. The Actor-System interaction below describes implemented behavior; unimplemented extensions remain in section18.

## 6. Trigger
Teacher chooses the corresponding action in Teacher Assignment editor: Save Deadline and Scale Only.

## 7. Preconditions
- PRE-1: Teacher is signed in, active, email verified and not suspended from teaching.
- PRE-2: The selected Course and required parent resources exist and are not deleted.
- PRE-3: Teacher owns the Course; content changes additionally require an editable Course status.
- PRE-4: Actor supplies the required inputs listed in section13.

## 8. Postconditions
**Success:** The configured deadline is persisted. Existing submissions, grades and feedback remain unchanged.

**Failure:** No unauthorized data is exposed or updated. Validation/conflict failures preserve existing records. Technical multi-step failure recovery/limits are described in sections11 and15; full cross-collection transactions are not implied.

## 9. Normal Flow
1. Teacher opens an existing Assignment.
2. System authenticates the Teacher and verifies ownership through its Course.
3. Teacher enters a local deadline or clears the deadline.
4. System validates the timestamp and explicit timezone in the submitted instant.
5. System saves the UTC deadline without modifying existing submissions.
6. System displays the deadline in the viewer local timezone; future submission requests are evaluated against server time.

## 10. Alternative Flows
AF1.NF3: Teacher clears the deadline. System saves null; subsequent submissions have no deadline gate. Continue NF6.
AF2.NF3: Teacher changes only deadline/scale on a live Course. Settings-only save is allowed for the owner without editing content; continue NF4.

## 11. Exceptions
EX0.NF2: Authentication, teaching permission or ownership fails. System returns401/403 (or404 for unavailable parent resources), exposes no protected result, and ends the use case.

EX1.NF4: Invalid date or timestamp without timezone: reject and show field errors; return NF3.
EX2.NF6: Student submits at or after the stored deadline: reject the new submission, preserve the previous one, and end that submission attempt.

## 13. Input/Data Validation
deadline: null or finite ISO timestamp with Z or numeric offset. UI datetime-local is converted to an ISO instant. Boundary: submittedAt < deadline is accepted; equality is rejected. No automatic extension or late-submission flag.

## 14. Priority and Frequency of Use
Priority: High (Proposed planning value). Frequency: As needed during Course preparation, assessment or review; actual usage frequency is not measured.

## 15. Other Information and Assumptions
Per-student extensions and accepting late submissions are outside this iteration. Updating a deadline into the past is allowed and affects later requests only.
