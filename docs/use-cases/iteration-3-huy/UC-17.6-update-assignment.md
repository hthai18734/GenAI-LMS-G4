# UC-17.6 Update Assignment — Proposed ID

Status: implementation-aligned specification draft for an existing function.
UC-17.6 is a proposed identifier, not an approved SRS catalogue entry. Existing
I3-HUY rules retain their local repository identifiers; DRAFT-ASG rules below are
draft-local identifiers, not official BR numbers. Priority/frequency are planning
proposals. Author/date identify this specification draft, not the original code.

## a. Functional Description

| Item | Description |
|---|---|
| **ID and Name** | **UC-17.6 Update Assignment (Proposed ID)** |
| **Created By** | Tạ Gia Huy — CE182405 — HuyTGCE182405 |
| **Date Created** | 08/11/2026 |
| **Primary Actor** | Teacher |
| **Secondary Actors** | None |
| **Description** | Allows the Teacher who owns the Course to update an existing Assignment's title, instructions, related Lesson, optional prompt document, deadline and grading settings, subject to Course editing and grading restrictions. |
| **Trigger** | Teacher selects **Edit assignment** in Course Activities or **Edit** in the Existing assignments list. |
| **Preconditions** | PRE-1: Teacher is authenticated and teaching privileges are not suspended.<br>PRE-2: The Assignment and its Course exist, are not deleted, and the Teacher owns the Course.<br>PRE-3: To change title, instructions, related Lesson or prompt document, the Course status must be **DRAFT**, **REJECTED** or **APPROVED**. Deadline/scale-only updates follow AF-3. |
| **Postconditions** | POST-1: Accepted changes are persisted on the same Assignment; its identifier and Course relationship are preserved.<br>POST-2: Existing Student submissions, answers, submission files, scores and feedback are not rewritten by this operation.<br>POST-3: The system displays a success message and updates the Assignment in the Existing assignments list. |
| **Normal Flow** | **NF-1: Update Assignment Process**<br>1. Teacher opens the Course's Quizzes & Assignments tab and selects **Edit assignment**.<br>2. GenAI-LMS verifies access and retrieves the saved Assignment, related Lessons and current document information.<br>3. GenAI-LMS displays the existing Assignment values in the editor.<br>4. Teacher modifies the required fields and optionally selects a replacement prompt document.<br>5. Teacher selects **Save Assignment Changes**.<br>6. GenAI-LMS validates Teacher ownership, Course editability, editable fields, Lesson relationship, document and grading settings.<br>7. GenAI-LMS saves the accepted changes. If a new document was supplied, it becomes the Assignment prompt document.<br>8. GenAI-LMS displays **"Assignment updated successfully."** and refreshes the saved Assignment in the Existing assignments list. |
| **Alternative Flows** | **AF-1: Cancel editing**<br>1. Teacher selects **Cancel Editing** before saving.<br>2. GenAI-LMS returns to the Course Activities tab.<br>3. Unsaved field changes and the locally selected replacement file are discarded.<br><br>**AF-2: Keep the existing prompt document**<br>1. Teacher saves without selecting a new document.<br>2. GenAI-LMS retains the existing document reference.<br><br>**AF-3: Update deadline and scale only**<br>1. Teacher selects **Save Deadline and Scale Only**.<br>2. GenAI-LMS validates ownership and grading settings, then updates only the deadline/scale fields.<br>3. This settings-only operation is also available for a live Course; grading-scale locks still apply.<br><br>**AF-4: Remove the deadline**<br>1. Teacher clears the deadline and saves through the appropriate save action.<br>2. GenAI-LMS stores a null deadline, meaning no deadline is configured. |
| **Exceptions** | **EX-1: Invalid input** — Missing/oversized title, empty instructions, invalid deadline, unsupported fields, invalid numerical settings or invalid document: show an error and do not report a successful update.<br>**EX-2: Unauthorized access** — Unauthenticated user, wrong role, suspended teaching privileges or another Teacher's Course: deny the operation.<br>**EX-3: Unavailable Assignment/Course/Lesson** — Reject missing/deleted resources or a Lesson from another Course.<br>**EX-4: Course not editable** — Reject content/document changes while the Course is outside DRAFT, REJECTED or APPROVED.<br>**EX-5: Locked or changed grading settings** — Reject a forbidden scale change or a conflicting scale update; Teacher reloads the latest settings.<br>**EX-6: Request/storage failure** — Display an error. If the response outcome is uncertain, Teacher reloads the Assignment before retrying; the UI must not claim an unconfirmed success. |
| **Priority** | Medium — proposed planning classification. |
| **Frequency of Use** | Occasionally, when preparing or maintaining Assignments — proposed. |
| **Business Rules** | I3-HUY-R01, I3-HUY-R04, I3-HUY-R05, DRAFT-ASG-UPD-01, DRAFT-ASG-UPD-02, DRAFT-ASG-UPD-03, DRAFT-ASG-UPD-04. |
| **Other Information** | Main API: `PATCH /api/teacher/assignments/:assignmentId`.<br>Main UI: `TeacherAssignmentFormPage`.<br>The full save action refreshes the existing-assignment list and clears the editor; it does not guarantee that the screen remains in edit mode after saving.<br>Document removal without replacement and moving the Assignment to another Course are not provided by this flow. |
| **Assumptions** | Teacher reviews the selected Assignment and replacement document before saving. Formal UC/BR numbering must be reconciled with the project's authoritative SRS registry. |

## b. Business Rules

| ID | Business Rule | Business Rule Description |
|---|---|---|
| **I3-HUY-R01** | Teacher Ownership and Course Editing | Only an authenticated Teacher with teaching privileges who owns the Course may update its Assignment. Title, instructions, related Lesson and prompt document changes require Course status DRAFT, REJECTED or APPROVED. Settings-only updates do not use that content-editability restriction. |
| **I3-HUY-R04** | Assignment Deadline | A configured deadline is stored as a UTC instant and displayed in local time. API timestamps require a timezone offset or Z. A null deadline removes the limit. Server time at or after the deadline closes subsequent submissions/resubmissions. Changing a deadline does not invalidate previously accepted submissions; a past deadline is allowed and affects later requests. |
| **I3-HUY-R05** | Explicit Grading Scale | Numeric maximum score must be finite and between 0.000001 and 1000000. A configured passing score must be finite, non-negative and no greater than the maximum score; it requires a maximum score. Used/locked numerical grading scales cannot be changed. Resending unchanged scale values does not constitute a scale change. |
| **DRAFT-ASG-UPD-01** | Assignment Field Validation | The title must contain 1–200 characters after trimming; instructions must not be empty after trimming. The update must contain at least one supported editable field. The API rejects unsupported fields. |
| **DRAFT-ASG-UPD-02** | Lesson and Course Consistency | A selected Lesson must exist, be active and belong to the Assignment's Course. Clearing the Lesson makes the Assignment Course-level. The Assignment's Course cannot be reassigned through this operation. |
| **DRAFT-ASG-UPD-03** | Prompt Document Replacement | At most one prompt file may be selected per request. It must be a non-empty PDF, DOC or DOCX file, no larger than 25 MiB, and pass format/content checks. A new accepted document replaces the current reference; omitting a new file preserves the current document. Document access remains authenticated and authorized. |
| **DRAFT-ASG-UPD-04** | Preserve Student Assessment Records | Updating Assignment metadata/settings does not overwrite existing Student submissions, submission files, grades or feedback. Changes can affect future access, submissions and live completion evaluation according to the applicable Course rules. |
