## 5. Description
Create Section within an owned Course. The Actor-System interaction below describes implemented behavior; unimplemented extensions remain in section18.

## 6. Trigger
Teacher selects Create Section in curriculum, opening a separate page.

## 7. Preconditions
- PRE-1: Teacher is signed in, active, email verified and not suspended from teaching.
- PRE-2: The selected Course and required parent resources exist and are not deleted.
- PRE-3: Teacher owns the Course; content changes additionally require an editable Course status.
- PRE-4: Actor supplies the required inputs listed in section13.

## 8. Postconditions
**Success:** The new Section belongs to exactly one Course and appears in its curriculum. No Lesson is moved automatically.

**Failure:** No unauthorized data is exposed or updated. Validation/conflict failures preserve existing records. Technical multi-step failure recovery/limits are described in sections11 and15; full cross-collection transactions are not implied.

## 9. Normal Flow
1. Teacher opens the Course curriculum and selects Create Section.
2. System authenticates the Teacher, checks Course ownership and editable status.
3. Teacher enters Name and optional Description on the separate screen.
4. System validates trimmed Name1-200 and Description up to5000.
5. System saves Section.title/description under that Course with its next order.
6. System displays a success toast and returns to curriculum; the Lesson form only selects an existing/default Section.

## 10. Alternative Flows
AF1.NF3: Teacher selects General for a Lesson instead of creating a Section. System resolves/reuses the default Section during Lesson save; continue in the Lesson save flow.

## 11. Exceptions
EX0.NF2: Authentication, teaching permission or ownership fails. System returns401/403 (or404 for unavailable parent resources), exposes no protected result, and ends the use case.

EX1.NF4: Empty, non-string, unsupported fields or title over 200 characters: show validation errors, keep the form, return to NF3.

## 13. Input/Data Validation
name: trimmed string1-200; description: optional text up to5000. Legacy title accepted, but name and title together rejected. Course ID from route cannot be overridden; order assigned by service. Stored Section.title retains compatibility; Section.description added. Lesson.sectionId must match Course.
