## 4. Actors
Primary Actor: **Teacher owning the Course**.
Secondary Actors: None; databases and storage are internal system components.

## 5. Description
Generate Grade Report within an owned Course. The Actor-System interaction below describes implemented behavior; unimplemented extensions remain in section18.

## 6. Trigger
Teacher chooses the corresponding action in Gradebook / Download Report (PDF) (PDF).

## 7. Preconditions
- PRE-1: Teacher is signed in, active, email verified and not suspended from teaching.
- PRE-2: The selected Course and required parent resources exist and are not deleted.
- PRE-3: Teacher owns the Course; content changes additionally require an editable Course status.
- PRE-4: Actor supplies the required inputs listed in section13.

## 8. Postconditions
**Success:** The PDF reflects the authorized report dataset and its Gradebook calculation rules; export does not change grades.

**Failure:** No unauthorized data is exposed or updated. Validation/conflict failures preserve existing records. Technical multi-step failure recovery/limits are described in sections11 and15; full cross-collection transactions are not implied.

## 9. Normal Flow
1. Teacher selects Download Report (PDF) in Gradebook.
2. System verifies authentication and Course ownership.
3. Backend assembles all enrolled pages using the same live shared completion evaluator as Gradebook.
4. Browser renders latest scores, Lesson/video counts, completion readiness and remaining requirements as PDF using textContent.
5. Browser downloads the report and displays a success toast.

## 10. Alternative Flows
AF1.NF3: No students: export an empty roster with Course information.
AF2.NF3: Missing or ungraded activities: preserve incomplete and explicit states; never substitute zero; continue NF4.

## 11. Exceptions
EX0.NF2: Authentication, teaching permission or ownership fails. System returns401/403 (or404 for unavailable parent resources), exposes no protected result, and ends the use case.

EX1.NF3: Backend data loading fails: show error and do not generate a misleading successful report; retry NF1.
EX2.NF5: Browser rendering/download fails: show error; the source grades are unchanged, retry NF1.

## 12. Business Rules
I3-HUY-R01, I3-HUY-R06, I3-HUY-R08, I3-HUY-R10. Definitions and approval status are in [README](README.md#rule-identifiers-and-review-status). Local IDs are not claimed to be official RDS identifiers.

## 13. Input/Data Validation
Course ID must be valid and owned. Report covers every roster page, not just the visible Gradebook page. PDF only. Actor-controlled names/titles use textContent. Vietnamese is rendered through the existing HTML-to-PDF browser library. No CSV/spreadsheet is introduced, so spreadsheet formula interpretation is not applicable.

## 14. Priority and Frequency of Use
Priority: High (Proposed planning value). Frequency: As needed during Course preparation, assessment or review; actual usage frequency is not measured.

## 15. Other Information and Assumptions
Live reads, not a frozen official snapshot. Pause grading for an official consistent export. PDF preview was inspected with Vietnamese names; wide/large rosters need further review. No weighted final score remains.

## 16. Acceptance Criteria
- AC-1: Normal flow yields the stated success postcondition with persisted/source-aligned values.
- AC-2: A different Teacher and an unauthenticated user cannot perform the protected action.
- AC-3: Each validation and alternate flow above preserves the documented zero/null, relation, time or revision distinction.
- AC-4: UI exposes loading/busy, empty where applicable, and error states without claiming success on failure.
- AC-5: Repeated reads/calculation do not create duplicate grades; writes follow their documented update semantics.
