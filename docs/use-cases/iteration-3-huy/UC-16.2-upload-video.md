## 5. Description
Upload Video within an owned Course. The Actor-System interaction below describes implemented behavior; unimplemented extensions remain in section18.

## 6. Trigger
Teacher chooses the corresponding action in Teacher lesson editor.

## 7. Preconditions
- PRE-1: Teacher is signed in, active, email verified and not suspended from teaching.
- PRE-2: The selected Course and required parent resources exist and are not deleted.
- PRE-3: Teacher owns the Course; content changes additionally require an editable Course status.
- PRE-4: Actor supplies the required inputs listed in section13.

## 8. Postconditions
**Success:** Lesson retains its ID and contains a valid video source and metadata. Local media remains protected by authorization.

**Failure:** No unauthorized data is exposed or updated. Validation/conflict failures preserve existing records. Technical multi-step failure recovery/limits are described in sections11 and15; full cross-collection transactions are not implied.

## 9. Normal Flow
1. Teacher opens the Lesson editor in an editable Course.
2. System authenticates the Teacher and checks Course ownership before accepting bytes.
3. Teacher selects a video file and starts upload.
4. System validates one file, supported MIME, size and basic container signature.
5. System stores the file locally and registers its owner, Course and expiry.
6. Teacher selects a Section and saves the Lesson.
7. System validates matching Course/Section, upload ownership and expiry, then saves video reference and metadata on the Lesson.
8. System confirms the save; an authorized learner can play the protected video.

## 10. Alternative Flows
AF1.NF3: Teacher enters an HTTP(S) URL instead. System validates its scheme, performs no server-side fetch and records an external source when Lesson is saved; continue NF6. Browser/provider playback support remains source-dependent.
AF2.NF6: Teacher cancels or replaces the upload. System requests discard; abandoned uploads expire after 24 hours and the periodic sweep retries cleanup. End without changing the Lesson.

## 11. Exceptions
EX0.NF2: Authentication, teaching permission or ownership fails. System returns401/403 (or404 for unavailable parent resources), exposes no protected result, and ends the use case.

EX1.NF4: Unsupported/spoofed/oversized file: reject and retain the editor, return NF3.
EX2.NF7: Metadata persistence fails: preserve the existing Lesson, discard the newly verified pending upload where possible, and report failure; return NF3. Failed discard keeps its retry record.

## 13. Input/Data Validation
video: exactly one multipart file, <=200 MiB; MP4, WebM, OGG, MOV, AVI or Matroska MIME allowlist with basic signature check. URL: HTTP(S) only. New local reference must belong to the current Teacher/Course and not be expired. Filename is generated; metadata cannot be supplied as arbitrary Lesson fields.

## 14. Priority and Frequency of Use

## 15. Other Information and Assumptions
