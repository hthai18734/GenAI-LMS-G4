## a. Functional Description

| Item | Description |
|---|---|
| **ID and Name** | **UC-17.7 Delete Assignment (Proposed ID)** |
| **Created By** | Tạ Gia Huy — CE182405 — HuyTGCE182405 |
| **Date Created** | 08/11/2026 |
| **Primary Actor** | Teacher |
| **Secondary Actors** | None |
| **Description** | Allows the Teacher who owns the Course to remove an Assignment from active use through soft deletion while retaining the stored Assignment and related assessment records. |
| **Trigger** | Teacher selects **Delete** for an Assignment in the Existing assignments list. |
| **Preconditions** | PRE-1: Teacher is authenticated and teaching privileges are not suspended.<br>PRE-2: The Assignment and its Course exist, are not deleted, and the Teacher owns the Course.<br>PRE-3: The Course status is **DRAFT**, **REJECTED** or **APPROVED**. |
| **Postconditions** | POST-1: The Assignment's `deletedAt` is set to the server deletion time.<br>POST-2: The Assignment is excluded from subsequent active Assignment lists and active assessment evaluation.<br>POST-3: Existing submissions, grades, feedback and document references remain stored; this operation does not cascade-delete them.<br>POST-4: The system removes the Assignment from the current list and displays a success message. |
| **Normal Flow** | **NF-1: Delete Assignment Process**<br>1. Teacher opens the Assignment editor for the Course and locates the Assignment under **Existing assignments**.<br>2. Teacher selects **Delete**.<br>3. The system displays a confirmation identifying the Assignment: **Delete assignment "[assignment title]"?**<br>4. Teacher confirms deletion.<br>5. GenAI-LMS verifies authentication, teaching privileges, Course ownership, Course editability and Assignment availability.<br>6. GenAI-LMS sets `deletedAt` on the Assignment without physically deleting the record.<br>7. GenAI-LMS removes the Assignment from the current list and displays **"Assignment deleted successfully."**<br>8. If the deleted Assignment was currently being edited, GenAI-LMS returns to the Course Activities tab; otherwise, it remains on the current Assignment editor/list. |
| **Alternative Flows** | **AF-1: Cancel deletion**<br>1. Teacher cancels the confirmation dialog.<br>2. No deletion request is sent and the Assignment remains unchanged.<br><br>**AF-2: Assignment has existing submissions**<br>1. GenAI-LMS performs the same ownership and Course-status checks.<br>2. Existing submissions do not independently block soft deletion.<br>3. The Assignment is soft-deleted; related submissions, scores, feedback and document references remain stored. |
| **Exceptions** | **EX-1: Unauthorized access** — Unauthenticated user, wrong role, suspended teaching privileges or another Teacher's Course: deny deletion.<br>**EX-2: Assignment or Course unavailable** — Missing/deleted Assignment or Course: report that the resource is unavailable; do not recreate it.<br>**EX-3: Course not editable** — Course status outside DRAFT, REJECTED or APPROVED: reject deletion.<br>**EX-4: Assignment changed during deletion** — If the active record can no longer be updated, report the conflict and ask Teacher to reload.<br>**EX-5: Request/storage failure** — Display an error. If the outcome is uncertain, Teacher reloads the list before retrying; an unconfirmed deletion must not be presented as successful. |
| **Priority** | Medium — proposed planning classification. |
| **Frequency of Use** | Occasionally, when removing an unnecessary Assignment — proposed. |
| **Business Rules** | I3-HUY-R01, DRAFT-ASG-DEL-01, DRAFT-ASG-DEL-02, DRAFT-ASG-DEL-03. |
| **Other Information** | Main API: `DELETE /api/teacher/assignments/:assignmentId`.<br>Main UI: the **Delete** button under **Existing assignments** in `TeacherAssignmentFormPage`.<br>The current UI uses a browser confirmation dialog. Restore/undelete and permanent deletion are not provided by this flow. |
| **Assumptions** | Teacher verifies the Assignment named in the confirmation. Retained records are not promised to remain accessible through normal active-Assignment APIs. Formal UC/BR numbering and a long-term retention policy require the authoritative project specification. |

## b. Business Rules

| ID | Business Rule | Business Rule Description |
|---|---|---|
| **I3-HUY-R01** | Teacher Ownership and Course Editing | Only an authenticated Teacher with teaching privileges who owns the Course may delete its Assignment. Deletion requires Course status DRAFT, REJECTED or APPROVED; PUBLIC and PENDING_REVIEW do not satisfy this requirement. |
| **DRAFT-ASG-DEL-01** | Confirmed Soft Deletion | The UI requests confirmation before deletion. On an accepted API request, the system sets `deletedAt` instead of physically deleting the Assignment. Confirmation is an interface step; the API still enforces authorization and Course status. |
| **DRAFT-ASG-DEL-02** | Preserve Related Records | Soft deletion does not cascade-delete Assignment submissions, answers, grades, feedback or associated document references. The presence of submissions is not an additional deletion blocker in the current implementation. Retention does not imply that active-Assignment endpoints will continue to expose these records. |
| **DRAFT-ASG-DEL-03** | Exclude Deleted Assignments from Active Use | Subsequent active Assignment queries exclude records whose `deletedAt` is not null. A deleted Assignment is omitted from Student available-assignment lists and the next live Gradebook/completion evaluation. Deletion itself does not issue a certificate or rewrite historical assessment records. |
